Books can now be worked on locally with git: `git clone https://git@<admin host>/api/books/<id>/git`, edit, and `git push` to `main`. The push is served by git smart HTTP on the admin origin with per-book API tokens (hash-only, revocable, shown once; Basic auth, username `git`), enforced to a single `main` branch by a pre-receive hook that also applies the storage quota to the pushed tree; deletes, other refs, tags and non-fast-forwards are rejected. A push never triggers a publish build — it only updates the source size, the audit log (`book.push`) and the new `commit_count`; the instance setting "a git push also builds the preview" (default off) additionally queues a preview-only build. Publishing is recorded as version tags (`v1`, `v2`, … plus a moving `published` tag; only the last two are kept, an optional note is stored on the build) and the live site can be rolled back to a tag — instantly when its build is still kept, otherwise by rebuilding it. The book page gained a "Work locally (git)" block with the clone command and token management, a publish note, rollback buttons on tagged builds, and a staleness hint ("main is N commits ahead of the live site"). Editor saves keep their CAS semantics against pushes: a save based on a pre-push version is refused with a conflict, a push after an editor commit is non-fast-forward.
